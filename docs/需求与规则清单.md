## 2. 系统目标、范围与操作角色

建设简化广州中考公办高中录取模拟系统，形成数据准备、运行校验、四批投档、查询解释、统计导出及对照分析的闭环。所有考生均为虚构数据。

| ID | 范围要求 | 来源 |
| --- | --- | --- |
| S-01 | 全体考生视为具有公办高中报考资格；不区分户籍、随迁、应往届、学籍年限、区内外与跨区限额 | 任务书二 |
| S-02 | 仅模拟公办普通高中；不含民办、中职、综合高中、港澳班或中外合作项目 | 任务书二 |
| S-03 | 中考总分直接作为投档分；不考虑加分、同等条件优先及参考科目等级 | 任务书二 |
| S-04 | 第一批仅保留自主招生，资格与考核排名直接输入；第二批名额分配表直接输入，不实现考试组织或电脑派位 | 任务书二、三 |
| S-05 | 仅第三批统招高中可设第一、第二批计划；每所高中仅在第三或第四批之一接收统招计划 | 任务书二、三 |
| S-06 | 不模拟退档、放弃录取、报到注册及正式补录，不建设真实考试报名系统 | 任务书二 |

操作角色为“数据准备人员”“模拟操作人员”“查询与分析人员”，对应操作职责，可由同一名组员兼任。任务书未要求多用户登录或权限系统；是否增加账号功能另行评审，不作为当前必做范围。

## 4. 投档规则清单

| ID | 必须遵循的规则 | 来源 / 验证重点 |
| --- | --- | --- |
| R-01 | 按第一、第二、第三、第四批依次执行；前批完成及必要结转完成后才能进入后批 | 任务书三.3、三.4；前批落选者可继续 |
| R-02 | L、G₁、Δ为本次运行输入，Δ默认 40；低于 L 不投档；第三、四批统一以 L 为门槛 | 任务书三.1；等于 L 可进入末档；DEC-04 |
| R-03 | 第一梯度为分数 ≥ G₁，后续以 Δ逐档下降，最后一档截至 L；等于梯度线归入较高梯度 | 任务书三.1；梯度线上下 1 分 |
| R-04 | 第一批只对填报该校、资格有效且总分 ≥ 计划控制线者，按该校输入考核排名升序录至满额 | 任务书三.2；不能直接按中考总分替代考核排名；DEC-01、DEC-04 |
| R-05 | 第二至第四批均先高梯度后低梯度；同梯度先第一志愿，再第二志愿，依次处理 | 任务书三.3；禁止对每名考生连续扫描其全部志愿 |
| R-06 | 同梯度、同志愿轮次竞争同一计划者，按总分降序、同分序号升序录取 | 任务书三.3；高梯度后志愿可优先于低梯度前志愿 |
| R-07 | 第二批按“高中 + 初中”子计划隔离竞争；不同初中名额不能互相挤占；总分须达到对应子计划控制线 | 任务书三.3；同校另一初中有余额也不能借用；DEC-04 |
| R-08 | 考生一旦录取，立即更新本次运行状态，退出本批其他志愿及所有后批 | 任务书三.4；每运行每考生最多一条录取；教师补充 |
| R-09 | 第一批结束后，将各高中余额转入其第三批；第二批结束后，按高中汇总各初中子计划余额并转入第三批 | 任务书三.4、讨论提示；不转第四批 |
| R-10 | 每个来源计划在一次运行中仅结转一次，保存来源、去向与数量；重复请求不能重复增加第三批名额 | 任务书三.4；幂等与故障重试；第 5 节、任务书五 |
| R-11 | 第三、第四批余额不互转；无人报考或合格考生不足时允许未完成计划，不强行录满 | 任务书三.4、五 |
| R-12 | 对第三批高中，总计划为 N 时，有自招资格则自招为 ⌊N × 10%⌋，否则为 0；名额分配为 ⌊N × 50%⌋；第三批初始统招为 N 减去前两项 | 任务书二；DEC-02 |
| R-13 | 第四批高中只设第四批计划；年度总计划分解、后续结转分别记录，不能重复计入总供给 | 任务书二、三.4 |

## 5. 冗余设计：必须实现的约束

冗余用于减少反复从明细汇总余额、查询考生是否已录取的开销。**必须设计、同步维护并验证以下冗余信息**；不能只在报告里提及。下表是逻辑要求，物理表名、分表方式和事务粒度在数据库及算法设计中确定。

| ID | 冗余对象 / 建议逻辑键 | 至少维护的字段 | 更新时机与核对依据 |
| --- | --- | --- | --- |
| RD-01 | 考生运行状态：运行编号 + 考生编号 | 是否已录取、录取批次、录取学校、录取计划 | 录取成功时立即更新；未录取时相关去向为空；与录取明细核对 |
| RD-02 | 第一批计划运行余额：运行编号 + 计划编号（高中） | 初始数、已录取数、转出数、余额 | 录取时扣减；批末结转时转出；与录取明细、结转流水核对 |
| RD-03 | 第二批子计划运行余额：运行编号 + 计划编号（高中 + 初中） | 初始数、已录取数、转出数、余额 | 校内投档扣减；批末按高中汇总结转，保留来源子计划明细 |
| RD-04 | 第三批计划运行余额：运行编号 + 计划编号（高中） | 初始数、转入数、已录取数、余额 | 第一、二批结转时增加转入；第三批录取时扣减 |
| RD-05 | 第四批计划运行余额：运行编号 + 计划编号（高中） | 初始数、已录取数、余额 | 仅第四批录取扣减；无第一、二批转入 |
| RD-06 | 结转流水 | 运行、来源计划、目标计划、数量、来源批次、执行标识或等价幂等依据 | 与来源转出及目标转入同时生效；重试不能产生第二次结转 |

### 5.1 一致性与恢复

- **RD-07 原子更新**：一笔录取的录取明细、考生状态、计划已录取数与余额必须一起成功或一起失败；结转流水、来源转出、来源余额及目标转入、目标余额亦同。内存运算与批量落库也必须保证持久化边界一致，失败时回滚或从一致检查点恢复。
- **RD-08 运行隔离与幂等**：不同运行不能共享可变余额或状态。相同请求重试不得重复录取、扣减或结转；同一运行的重复点击应拒绝或返回已有结果。重新模拟须生成独立运行，按快照初始化状态和余额。
- **RD-09 完成状态可信**：结果、冗余数据和日志尚未完整保存或对账失败时，不得将运行标为成功完成。展示进度须区分计算中、保存中、已完成和失败等状态，具体名称由实现确定。
- **RD-10 对账与修复**：提供可执行对账脚本或等价功能。发现差异须标记异常，禁止静默改写已完成结果；修复须留记录或新建运行。建议以冻结输入、录取明细和结转流水为核对依据。

### 5.2 对账公式与验收示例

每条计划：**初始名额 + 转入数 − 转出数 = 已录取数 + 剩余数**。第一、二批转入为 0；第三批转出为 0；第四批转入、转出均为 0。结转后来源余额归零，并保留转出数量，不得把它再次作为可录取余额。

必须同时核对：已录取数等于对应明细数量；考生状态与明细去向一致；来源转出总量等于目标转入总量及流水数量；全校、全运行的汇总与明细一致。跨批汇总总计划时不得同时把来源初始数和目标转入数算作新增供给。

人工验收示例：某高中第一批初始 2、录取 1，第二批两个子计划分别初始 2、录取 1和初始 1、录取 0，第三批初始 3。第一批结转 1，第二批结转 2，第三批有效名额为 6；高中初始总供给为 8。重复结转后第三批仍为 6。该示例验证余额，不替代完整小数据预测试。另需注入“已写明细、尚未更新余额”等失败点，验证原子回滚或等价恢复。

## 7. 用例说明

以下角色均为模拟系统操作者，不表示已经实现登录权限。

| 用例 | 操作角色 / 前置条件 | 主流程 | 异常与成功后状态 | 关联需求 |
| --- | --- | --- | --- | --- |
| UC-01 准备数据 | 数据准备人员；尚未冻结的输入版本 | 录入或导入 → 校验 → 查看错误并修正 → 全量通过后提交；可只校验不落库 | 无效记录不得进入有效快照；成功后数据版本可用于新建运行 | F-01、V-* |
| UC-02 生成虚构数据 | 数据准备人员；生成配置合法 | 选择规模与种子 → 生成学校、计划、考生、资格、志愿 → 校验并保存配置 | 校验失败提示原因；成功后同配置可复现 | F-02、D-08 |
| UC-03 创建并执行模拟 | 模拟操作人员；有效输入与参数 | 校验 → 冻结输入 → 初始化运行状态/余额 → 分批或完整投档 → 结转 → 保存与对账 | 重复执行不叠加；失败不能显示成功；完成后结果可查询 | F-03、F-04、R-*、RD-* |
| UC-04 查询考生及计划 | 查询人员；选定运行 | 按考生或计划筛选 → 查看录取、志愿处理、原因、余额与流水 | 不存在的对象提示；未完成运行需说明数据状态 | F-05、F-06 |
| UC-05 统计并导出 | 分析人员；选定完成运行 | 选择统计维度 → 查看统计 → 导出 | 空计划显示“无”；导出与界面及明细口径一致 | F-07、ST-* |
| UC-06 滑档对照 | 分析人员；原始案例及人工预期已保存 | 原运行 → 复制输入版本 → 仅改目标考生志愿 → 新建完整运行 → 对照 | 原运行保持可追溯；报告明确唯一修改及其影响 | F-08、F-09 |

UC-03 的分批操作必须校验前批与结转完成状态；不能从第一批直接跳至第三批而略过第二批。UC-06 不允许沿用旧录取状态或旧余额。

## 8. 统计口径

| ID | 统计定义 | 验收要点 |
| --- | --- | --- |
| ST-01 | 计划最低录取分 = 该计划实际录取考生总分的最小值 | 无人录取显示“无”，不能显示 0；任务书四.3、DEC-07 |
| ST-02 | 末位考生 = 按该计划实际录取顺序最后录取者 | 无人录取时显示“无”；分别报告其总分、志愿序号、同分序号，不用最低分考生替代；DEC-07 |
| ST-03 | 计划完成率定义为该计划已录取数 / 有效名额；有效名额 = 初始 + 转入 − 转出 | 分母为 0 时统一采用“无／不适用”口径，界面、接口及导出保持一致；DEC-07 |
| ST-04 | 学校总体计划数按初始计划总和计，录取数按去重明细计；批次计划分别展示初始、转入、转出及余额 | 不能重复累加结转数量；总体与分批统计清楚区分；任务书四.2(4)、五 |
| ST-05 | 运行未录取人数 = 快照考生数 − 已录取考生数；低于 L 等未录取考生仍包含在总体人数中 | 不能仅以具备投档资格人数作总体分母；其他筛选口径应标注；任务书四.2(4) |

任务书最低示例：G₁=720、Δ=40、L=600；A校统招2人，甲690分第一志愿A，乙710分第二志愿A且其第一志愿校已满。二者同处第二梯度，先甲后乙；最低分690，末位乙710分、志愿序号2。该例说明 ST-01 与 ST-02 不同。

## 10. 预测试与需求追踪

完整开发前提交小数据输入及人工预期，建议2所初中、3—4所高中、12—20名考生、每计划1—3人，可用多个独立场景。人工预期须先于系统结果形成，并由至少另一成员复核。

| 测试 ID | 必测场景 / 预期 | 关联需求 |
| --- | --- | --- |
| T-01 | 高梯度后志愿先于低梯度前志愿 | R-03、R-05 |
| T-02 | 同梯度低分第一志愿可先于高分第二志愿 | R-05、R-06 |
| T-03 | 同梯度同志愿先比总分，同分再比序号 | R-06、V-03 |
| T-04 | 恰等于L或梯度线可进入；低1分进入低档或不能投档 | R-02、R-03、V-07 |
| T-05 | 自招未获资格、未达线落选；达线者按考核排名 | R-04 |
| T-06 | 前批录取者不占后续计划；前批落选者可继续 | R-01、R-08、RD-01 |
| T-07 | 名额分配按所属初中隔离，不借其他初中余额 | R-07、RD-03 |
| T-08 | 第一、二批余额只转第三批一次，流水和余额一致 | R-09、R-10、RD-02～RD-06 |
| T-09 | 无人报考、志愿不足或分数不足不强行录满；空结果及零有效名额完成率显示正确 | R-11、ST-01～ST-03 |
| T-10 | 最低录取分与末位考生分别统计 | ST-01、ST-02 |
| T-11 | 重复考生、非法分数、重复志愿、无效计划、重复同分序号均拒绝并报告原因；只校验模式不落库，失败导入不产生部分数据 | V-01～V-08 |
| T-12 | 同快照复跑一致；新运行隔离，重试不叠加旧录取 | F-04、RD-08、N-03 |
| T-13 | 冗余状态、余额与录取明细及流水一致；中途失败、重试仍一致 | RD-07～RD-10 |
| T-14 | 两个滑档案例及仅改目标志愿的完整对照成立 | F-08、F-09 |
