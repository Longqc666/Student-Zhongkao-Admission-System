# 简化广州中考公办高中录取模拟系统

《软件系统开发实践》课程设计项目。系统以广州中考招生机制为业务背景，按照课程任务书中的统一简化规则，模拟公办高中招生计划、志愿投档和录取结果，并支持过程追溯和结果验证。

> **项目状态：规划阶段。** 当前仓库包含课程任务书和设计讨论资料，尚无可运行的系统代码。功能、分工和进度均为计划，后续根据组内讨论和实际进展更新。

## 项目资料

- [课程设计任务书](./软件系统开发实践课程设计任务书.docx)：需求、规则、验收与提交要求的依据。
- [设计讨论提示](./设计讨论提示.txt)：批次处理与名额结转的讨论记录。

本项目为教学模拟，**以课程任务书为准**，不代表真实招生政策，也不使用真实考生数据。

## 建设目标与范围

完成从基础数据管理、投档模拟到查询统计和测试验证的完整流程，做到结果可复现、录取过程可解释、计划余额可核对。

- 仅模拟公办普通高中；不区分户籍、区域等条件，不考虑政策加分等现实细则。
- 总分作为投档分；同分时使用同分序号，序号越小越优先。
- 模拟第一批自主招生、第二批名额分配、第三批和第四批统招；只给第三批招生高中设置第一、第二批计划。
- 不模拟退档、放弃录取、报到注册或正式补录。

### 录取规则摘要

| 批次 | 方式 | 志愿上限 |
| --- | --- | --- |
| 第一批 | 自主招生：检查志愿、资格和控制线，按校内考核排名录取 | 1 |
| 第二批 | 名额分配：考生仅竞争分配给所属初中的名额 | 3 |
| 第三批 | 指定示范性公办高中统招 | 6 |
| 第四批 | 指定非示范公办高中统招 | 6 |

第二至第四批按**批次 → 梯度从高到低 → 志愿顺序 → 总分降序、同分序号升序**处理。达到控制线或梯度线的边界分数可进入相应范围；低于最低控制线的考生不参与录取。已录取考生不再参与后续投档。

第一、第二批的剩余名额在批次结束后转入同校第三批，第二批须先按高中汇总各初中的剩余名额；每笔结转只执行一次并保留流水。第三、第四批余额不互转。学校最低录取分由结果产生，不可预先作为录取条件；最低录取分与实际录取顺序中的末位考生需分别统计。

## 计划实现的功能

- **基础数据**：管理和校验高中、初中、考生、计划、资格及志愿；支持导入和基于种子或配置的虚构数据生成。
- **投档模拟**：运行前校验，支持分批和完整运行；展示进度、余额及结转，保存输入快照或等价版本依据，防止已完成运行的输入被静默修改。
- **结果查询**：按考生、学校、初中、批次和计划查询录取、余额与志愿处理过程，解释未录取原因。
- **统计与导出**：统计计划数、录取人数、完成率、未录取人数及分数分布，分别展示最低录取分和末位考生信息，支持结果导出。
- **滑档对照**：构造至少两个高分滑档案例，分别体现某批次未录取及全部批次结束仍未录取；固定其他数据，只调整该考生志愿并重新完整投档，对比结果。

## 验证重点

预测试建议使用 2 所初中、3—4 所高中和 12—20 名考生；必要时拆成多个独立场景。人工预期应先于系统输出形成。

- 梯度优先、同梯度志愿优先、分数及同分序号排序，覆盖控制线和梯度线边界。
- 自主招生资格与考核排名、前批录取排除、第二批初中名额隔离。
- 剩余名额准确结转且不重复结转；不足额时不强行录满。
- 无人录取时最低分和末位考生显示“无”；分别验证最低分与末位考生。
- 检查重复考生、非法分数、重复志愿、无效计划和重复同分序号；同一快照重复运行结果一致。
- 核对每位考生最多录取一次、计划不超额、录取满足志愿与资格、名额收支平衡以及汇总与明细一致。
- 完成任务书要求的两个高分滑档案例及只调整该考生志愿的完整对照。

## 协作与交付约定

- 使用 Git 记录协作过程；建议按任务建立分支，通过 Pull Request 说明变更、测试结果并由其他成员复核。
- 讨论并记录各模块接口、数据口径与待决问题；合并前检查规则、测试和文档是否一致。
- 只使用虚构数据，不提交真实考生信息、密码或密钥。AI 如用于开发，应记录使用环节，并由成员核实代码、规则和测试结果。
- 最终提交源代码与版本记录、设计报告、测试材料、使用与部署说明、较大规模模拟数据及演示材料。每位成员应能解释自己的工作和关键规则。
